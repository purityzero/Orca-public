Orca 워크스페이스에서 작업할 Unity 프로젝트를 고르거나 바꾼다. 세션 처음이든 중간이든 같은 절차를 따른다.

## 1. 현재 상태를 다시 수집한다
Bash로 아래 두 명령을 실행한다. 세션 ID는 환경 변수 `CLAUDE_CODE_SESSION_ID`에서 읽는다. 저장소 위치는 PC마다 다르므로 경로를 고정하지 않고 git으로 루트를 찾는다.

```
cd "$(git rev-parse --show-toplevel)"
echo "{\"session_id\":\"$CLAUDE_CODE_SESSION_ID\"}" | node .claude/hooks/env-check.js
echo "{\"session_id\":\"$CLAUDE_CODE_SESSION_ID\"}" | node .claude/hooks/session-start-project-picker.js
```

- env-check 출력의 `systemMessage`(환경 체크 표)를 코드 블록으로 그대로 보여준다.
- picker 출력의 `systemMessage`가 프로젝트 목록이다. 번호를 그대로 보여준다. 목록이 없으면 "프로젝트가 없습니다."라고 쓰고 작업할 프로젝트 절대경로를 묻는다.
- 현재 확정된 프로젝트가 있으면 함께 알린다: `.claude/session-project/$CLAUDE_CODE_SESSION_ID.json`의 `title`·`path`.
- 실행 중인 Unity 에디터도 알린다(여러 개일 수 있다): PowerShell `Get-CimInstance Win32_Process -Filter "Name='Unity.exe'" | Select-Object ProcessId, CommandLine`에서 `-projectPath` 값.

## 2. 프로젝트를 정한다
- 인자가 있으면(`$ARGUMENTS`) 그것으로 정한다: 번호면 위 목록의 그 번호, 이름이면 목록의 같은 이름, 절대경로면 그 경로.
- 인자가 없으면 목록을 보여준 뒤 사용자에게 묻고 멈춘다. 임의로 고르지 않는다.

## 3. 중간에 바꾸는 경우 먼저 확인할 것
이미 다른 프로젝트로 확정돼 있었고 그 프로젝트에서 이번 세션에 파일을 고쳤다면, 바꾸기 전에 미커밋 변경과 미검증 상태를 사용자에게 알리고 `.claude/UNFINISHED.md`(그 프로젝트의 것)에 기록한다. 이전 프로젝트의 에디터는 닫지 않는다.

## 4. 고른 프로젝트를 연다
1. PowerShell로 `& "$(git rev-parse --show-toplevel)/OpenUnityProject.ps1" -ProjectPath "<프로젝트 절대경로>"`를 실행한다. 다른 프로젝트의 에디터는 그대로 두고 새 에디터를 하나 더 띄운다. 이미 그 프로젝트가 떠 있으면 스크립트가 건너뛴다.
2. `.claude/session-project/$CLAUDE_CODE_SESSION_ID.json`을 새 프로젝트로 덮어쓴다:
   `{"title": "<이름>", "path": "<프로젝트 절대경로>", "source": "asked", "confirmedAt": "<ISO8601>"}`
   이 파일이 이번 세션의 작업 대상이다. 이후 코드·프리팹·테이블 작업은 이 프로젝트에서만 한다.
3. 스크립트가 실패하면(에디터 미설치, Hub 목록에 버전 없음 등) 출력 문구를 그대로 알리고, 확정 기록은 사용자가 원할 때만 남긴다.

## 5. 알릴 것
- 지금 작업 대상 프로젝트와, 열려 있는 에디터 목록.
- Unity MCP는 세션이 시작될 때만 연결된다. 이 세션에서 MCP가 없었다면 새로 띄운 에디터도 이 세션에는 붙지 않는다. Play Mode 검증이 필요하면 새 세션을 열어야 한다. 에디터가 여러 개 열려 있으면 MCP가 어느 에디터에 붙는지는 아직 확인되지 않았다(`.claude/UNFINISHED.md` 「MCP 멀티 인스턴스」).
