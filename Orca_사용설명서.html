Orca
사용 설명서

GeometryDefender와 HouseRulez를 안전하게 열고, AI 에이전트에게 작업을 맡기고, 검증과 Git 마무리까지 이어가는 실전 안내서입니다.

1. Orca는 무엇인가요?

Orca는 Unity 게임 코드를 직접 보관하는 폴더가 아니라, 여러 Unity 프로젝트를 AI 에이전트와 함께 운영하기 위한 메타 작업공간입니다. 작업 규칙, 에이전트 역할, 프로젝트별 기록, 실행 스크립트와 검증 절차가 한곳에 모여 있습니다.

관리하는 것

  • Codex·Claude Code 역할 계약
  • C#/Unity 코딩 규칙
  • 클래스·프리팹·QA 기록
  • Unity 실행과 프로젝트 경로
  • 브랜치·검증·병렬 작업 규칙

직접 보관하지 않는 것

  • Unity 프로젝트의 실제 게임 코드
  • 프로젝트의 Library 폴더
  • PC마다 다른 절대경로
  • Unity 에디터 자체
핵심: 에이전트를 많이 켜는 것보다, 작업을 격리하고 결과를 diff와 테스트로 비교해 안전하게 채택하는 것이 목적입니다.

2. 평소 시작 순서

1

OrcaStart.cmd 실행

바탕화면 바로가기 또는 Orca 폴더의 파일을 엽니다.

2

Unity 프로젝트 선택

Unity Hub 등록 목록에서 번호를 선택합니다. 프로젝트에 맞는 Unity 버전이 자동 사용됩니다.

3

Unity와 Orca 실행

Unity가 먼저 실행되고 Orca가 이어서 열립니다. MCP for Unity는 에디터 로드 후 자동 연결됩니다.

4

작업 요청

대상 프로젝트, 증상, 원하는 결과를 말합니다. 필요한 탐색과 실행자 선택은 에이전트가 맡습니다.

Unity가 필요 없는 문서·저장소 작업이면 선택 화면에서 Enter를 눌러 취소해도 Orca는 계속 실행됩니다.

3. 작업 요청을 잘 쓰는 법

아래 네 가지가 있으면 정확도가 크게 올라갑니다.

항목예시
대상GeometryDefender의 카드 선택 UI
증상다시 열면 아이템 순서가 가끔 뒤집힘
원하는 결과항상 테이블 순서대로 표시
검증Play Mode에서 3회 열고 닫아 확인

요청 예시

“GeometryDefender 카드 선택 창에서 재사용된 아이템 순서가 뒤집히는 문제를 고쳐줘. 테이블 순서를 유지해야 하고 관련 클래스 문서도 갱신해줘. Unity 검증이 필요하면 재현 절차를 남겨줘.”

계산이나 표시 규칙은 실제 숫자 예시를 함께 주세요. “10000은 100%로 표시”처럼 기준이 구체적이면 재작업이 줄어듭니다.

4. 실행자 선택

작업우선 실행자
저장소 전체 분석·리팩터링·마이그레이션Codex
CLI·PowerShell·자동화·검사기·테스트Codex
문서-코드 정합성·중복 규칙 감사Codex
Unity MCP·Play Mode·씬/프리팹 시각 검증Claude Code QA
프로젝트 전용 기획·밸런스Claude 전문 에이전트

Codex는 Claude가 실패한 뒤 투입하는 후속 처리 전용이 아닙니다. 성격이 맞는 일은 처음부터 Codex가 맡아 분석, 구현, 검증, 문서 갱신까지 닫습니다. 사용자가 실행자를 지정하면 그 선택이 우선합니다.

5. 한 작업의 전체 흐름

요청→문서·경로 확인→실행자 선택→작업 브랜치→수정→검증→Codex Git 마무리

작업 전

  • 공통 운영 문서와 프로젝트별 UNFINISHED.md를 읽습니다.
  • 실제 프로젝트 경로는 LocalPaths.json에서 확인합니다.
  • 클래스·프리팹 수정 전 대응 기록 문서를 먼저 읽습니다.
  • Unity 동작 변경은 work/날짜-주제 브랜치에서 시작합니다.

작업 후

  • 가능한 컴파일·테스트·Play Mode 검증을 수행합니다.
  • 관련 클래스·프리팹 기록을 갱신합니다.
  • 검증하지 못한 것은 즉시 UNFINISHED.md에 남깁니다.
  • 최종 채택과 Git 처리는 Codex 메인 세션이 담당합니다.

6. 병렬 작업

적합

  • 원인 가설이 둘로 갈리는 버그
  • 같은 테스트로 비교 가능한 두 구현
  • 파일이 겹치지 않는 독립 도메인
  • 읽기 전용 분석·리뷰

부적합

  • 앞 단계에 의존하는 순차 작업
  • 여러 에이전트가 같은 파일 수정
  • 코드와 그 코드가 읽는 CSV를 분리
  • 성공 조건이 없는 경쟁
Unity 에디터와 MCP는 공유 자원입니다. Play Mode, 프리팹 편집, 에디터 검증은 한 번에 하나만 수행합니다. 워크트리에서 Unity를 열면 대규모 재임포트가 발생할 수 있습니다.

첫 병렬 실험은 에이전트 두 개로 시작합니다. 각 레인에 목표, 수정 허용 파일, 성공 조건, 금지 범위, 결과 형식을 명확히 줍니다.

8. Git 마무리

최종 stage → commit → merge → push → 병합 완료 브랜치 정리는 Codex 메인 세션이 담당합니다.

  • 서브에이전트와 Claude Code는 구현·검증·리뷰 결과를 인계합니다.
  • Codex는 전체 status와 diff를 보고 요청 범위만 stage합니다.
  • 사용자 변경은 임의로 되돌리거나 함께 담지 않습니다.
  • 검증 상태와 미완료 기록을 대조해 한국어 커밋 메시지를 씁니다.
  • push 성공과 포함 관계 확인 후에만 브랜치를 정리합니다.

9. 새 PC 설정

  1. Orca 저장소를 clone합니다.
  2. SetupLocalPaths.cmd를 실행합니다.
  3. Unity Hub 목록에서 프로젝트 원본 경로를 선택합니다.
  4. 없는 프로젝트는 건너뛰어 null로 둡니다.
  5. OrcaStart.cmd로 Unity와 Orca 실행을 확인합니다.
  6. MCP가 안 붙으면 MCP for Unity → Advanced → Auto-Start Server on Editor Load를 켭니다.

새 프로젝트 편입 시

  • Unity 표준 .gitignore, 기준 브랜치, remote 확정
  • 컴파일·데이터 테이블 검증 수단 준비
  • MCP와 Unity CLI 연결 확인
  • orca repo add --path <프로젝트 경로>
  • Agent Permissions는 Manual 권장
  • Orca의 프로젝트 문서 구조에 기록 편입

10. 자주 생기는 문제

프로젝트 목록에 안 보임

Unity Hub 등록 여부를 확인하고 SetupLocalPaths.cmd를 다시 실행합니다.

MCP가 자동 연결되지 않음

Auto-Start 설정과 uv/uvx 경로를 확인합니다. Unity 프로젝트 두 개를 동시에 열면 포트가 충돌할 수 있습니다.

Claude 에이전트가 안 보임

에이전트 목록은 세션 시작 때 고정됩니다. 파일 복구 후에도 안 보이면 --continue가 아닌 새 세션을 엽니다.

검증했는데 변경이 반영되지 않음

워크트리에서 실행한 검증이 열린 원본 프로젝트를 검사했을 수 있습니다. 변경을 원본에 적용한 뒤 순차 검증합니다.
