# Codex QA 절차 — 빠른 확인 (QA-작은 범위)

마지막 적용: 2026-11-25. Codex가 수정된 버그·특정 시나리오를 항목별로 재확인한다. 독립 QA·도구·증거 기준은 [CLI 정본](codex-qa-unity-cli.md)을 먼저 읽고, 배정·반환은 [인계 런북](codex-handoff.md)을 따른다.

- 여러 수정은 한 Play Mode 세션에서 순서대로 확인한다. 전체 플레이·장시간 관찰·밸런스 판단은 [전체 절차](codex-qa-full.md)를 쓴다.
- 같은 실패가 2~3회 반복되면 멈추고 원인을 해석한다. 도구 호출이 약 45회에 이르면 항목별 결과와 막힌 지점을 **QA 미완료**로 반환한다.
- 기본은 영상 없이 `script eval --file` 폴링과 `console get`·`Editor.log`로 판정한다.

## 절차

1. CLI 정본 §1~§2의 연결·최신 컴파일·자동 틱 준비를 수행한다. 미확인이면 중단하고 보고한다.
2. 확인할 항목을 전부 나열하고 CLI 정본 §3에 따라 기대값·독립 증거를 직접 정한다.
3. Play에 한 번 진입하고 실제 프레임 증가를 확인한다. 자동 틱을 우선하며 정지 대응은 CLI 정본 §2를 따른다.
4. 항목별 시나리오를 재현하고 조작 경로·폴링 값·해당 구간 로그를 확보한다. `ExecuteEvents.pointerClickHandler` 발송은 **핸들러 경로 확인**으로 적고 실제 클릭·물리 입력·히트 테스트 검증과 구분한다(CLI 정본 §3).
5. 각 항목의 **통과/실패/불일치/미확인**을 즉시 기록한다. 한 항목 실패로 중단하지 않고 나머지도 확인한다.
6. 시각 판정이 필요한 항목만 `editor invoke_menu`로 `Tools/QA/Start Recording`~`Stop Recording`을 짧게 실행한다. [전체 절차 §2~§3](codex-qa-full.md#2-녹화-실행-절차)의 파일 확인·프레임 추출·아티팩트 교차검증을 적용하고, 확보하지 못한 항목은 미확인으로 둔다.
7. Play를 종료하고 종료 직후 로그까지 확인한다(CLI 정본 §3).
8. 항목별 결과를 표나 목록으로 반환한다. 실패·별도 새 이슈는 전체 절차 §5의 형식으로 `.claude/qa/client-issues.md` 또는 `design-issues.md`에 기록한다. QA는 리포트만 남기고 코드는 고치지 않으며, Claude의 `quick-fix`·`client-bugfixer`에 인계한다.
