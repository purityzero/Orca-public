# 피드백 관련 된 내용

마지막 적용: 2026-11-25. 피드백·정정·재발 처리와 공용 규칙 저장 전에 읽는다.

## 피드백 관련 된 내용
- **작업자가 새로 제안한 공용 규칙**은 저장 전에 사용자 동의를 얻는다. **사용자가 이미 명확히 정정·확인한 규칙**은 아래 절차대로 바로 반영하며 동의를 다시 묻지 않는다.

### 피드백 반영 프로세스 (자가 진단 → 문서 수정)
작업 중 지적·정정·확인을 받으면 다음 순서로 처리한다.

1. **범위 구분**: 이번 한 건·특정 프로젝트의 사례는 해당 작업 기록에만 남긴다. 프로젝트와 무관하게 반복될 일반 규칙만 공용 문서에 반영하며 고유명사는 역할 수준으로 일반화한다.
2. **기존 항목과 대조**: 관련 규칙을 먼저 찾고, 있으면 새 항목 대신 기존 문장을 고친다. 반례가 있으면 단서를 붙이거나 단정을 완화한다. 없으면 관련 장에 추가하고 맞는 장도 없으면 새 장을 만든다.
3. **근거 기록**: 왜 바뀌었는지 한 줄 배경을 함께 남긴다.
4. **명확한 정정은 즉시 반영**: 사용자가 이미 정정·확인한 내용은 다시 묻지 않는다. 공용/프로젝트 범위를 판단할 수 없을 때만 확인한다. 작업자 자신의 새 일반화 제안에는 위 저장 전 동의 규칙을 적용한다.
5. **압축**: 예외가 누적되면 항목 전체를 재작성해 압축한다.

### 승격 사다리 — 같은 실수는 한 단계씩 위로 올린다

실수를 알아차리면 **런북·메모리를 먼저 검색한다.** 없으면 1회부터 런북에 기록하고, 이미 있으면 재발로 세어 한 단계 올린다. 이 문서에 있던 규칙을 어긴 경우도 같다.

| 횟수 | 어디에 | 성격 |
|---|---|---|
| **1회** | `runbook/{주제}.md` | 참고. 그 주제를 작업할 때만 읽는다 |
| **2회** | 메모리(`memory/`) | 매 세션 주입되어 안 찾아도 눈에 들어온다 |
| **3회** | 훅 | 안 지킬 수 없게 만든다. 매 턴 뜨고 조건 충족 시 스스로 꺼지는 형태 |

**적을 때 함께 남길 것**
- **마지막으로 실제 적용한 날짜** — 오래 안 쓰인 항목을 나중에 걸러내기 위해
- **왜 그렇게 되는지** — 현상만 적으면 비슷하지만 다른 상황에 잘못 적용된다

**주기적으로 걷어낸다.** 메모리는 용량이 한정돼 있고, 런북도 길어지면 안 읽힌다.
오래 적용되지 않은 항목은 아래로 강등하거나 지운다. 늘리기만 하면 결국 전부 안 읽힌다.

**런북은 자동 로드하지 않는다.** `.claude/rules/`에 두지 않는다 — 그 폴더는 매 세션 로드되어
컨텍스트를 잡아먹는다. 런북은 그 주제를 작업할 때 골라 읽는 자료다.

(근거: 2026-09-10 이미 기록한 비동기 UI 갱신 누락이 재발해 교착이 발생함)


### 사용자 용어 실수는 한 줄로 정정한다
사용자가 용어를 바꿔 말했으면(행↔열 등) 정정은 한 줄로 끝내고 원래 질문에 답한다. 실수를 짚는 설명·표·주의사항을 길게 붙이지 않는다.
(근거: 2026-11-16. "열"을 "행"으로 정정하면서 표와 주의사항 3개를 붙였더니 사용자가 "내가 잘못 말한 거니 간단하게만" 요청. 마지막 적용: 2026-11-16)

### 서식 정리 요청은 원문 문구를 그대로 둔다
사용자가 준 글을 마크다운 등으로 정리해 달라고 하면 문구·오타·이름·숫자는 그대로 두고 서식(제목·목록·표·코드 표시)만 바꾼다. 오타나 실제와 다른 내용이 보이면 파일에 반영하지 말고 답변에서만 알린다.
(근거: 2026-11-16. 메모를 마크다운으로 저장하면서 오타를 고치고 함수 이름·줄 번호를 현재 코드 기준으로 바꿨더니 사용자가 "내용은 수정하지 말고 깔끔하게" 정정. 마지막 적용: 2026-11-16)

### 원본 파일 백업을 만들지 않는다
저장소가 없는 프로젝트를 고칠 때도 수정 전 원본을 백업 폴더로 복사하지 않는다. 작업자 브리프에도 백업 지시를 넣지 않는다. 되돌릴 수단이 필요하다고 판단되면 백업하지 말고 사용자에게 먼저 묻는다.
(근거: 2026-11-17. 저장소 없는 Unity 프로젝트의 컴파일 스텁 작업 브리프에 백업 폴더 생성을 넣었더니 사용자가 "원본 백업 금지" 정정. 마지막 적용: 2026-11-17)

### 사용자에게 보이는 글에 내부 줄임 기호를 쓰지 않는다
실험 시나리오·방식을 S1·A~F·Q7OldKeep 같은 코드로만 쓰지 않는다. 처음 한 번 "이름 | 하는 일" 표로 풀고, 본문·표는 사람이 알아듣는 이름(예: "권장 방식", "소멸자가 붙잡은 에셋")으로 쓴다. 대조용 기호는 괄호 안에만 둔다. 채팅 답변과 보고서 둘 다 해당한다.
