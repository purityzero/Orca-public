# 서브에이전트 목록 복구

마지막 적용: 2026-11-25 (카카오톡 완료 알림 규칙은 사용자 요청으로 삭제)

아래의 9개 에이전트와 공통 규칙은 `AGENT.MD` 「위 9개 에이전트(Client 7 + Design 2) 공통 규칙」을 기준으로 한다.

상세 절차는 각 에이전트 정의 파일(`agents/{이름}.md`, 프로젝트에서는 `.claude/agents/{이름}.md`) 참고.

## 에이전트가 목록에 안 보이면
2026-11-25 사용자 결정으로 역할 에이전트의 기본 실행 경로는 **Orca 작업자(새 세션)**다(`AGENT.MD` 「Claude 역할 에이전트 실행 방식」). Orca 작업자는 마스터 `agents/{이름}.md`를 브리프로 읽게 하므로 아래 목록 문제의 영향을 받지 않는다. 이 절은 Agent 도구(`subagent_type`)를 쓸 때만 해당한다.

- **목록은 세션 시작 때 한 번 잡힌다.** 세션 도중 목록에서 빠졌다면 그 세션에서는 `sync`나 파일 재배치로 복구되지 않는다. `claude --continue`도 이전 세션 상태를 그대로 복원해서 복구되지 않는다. `--continue` 없이 새 세션을 열어야 SessionStart 훅이 돌고 목록이 새로 잡힌다. 넘길 내용이 길면 브리프 파일로 저장해 두고 새 세션에서 읽게 한다.
  (근거: 2026-08-25. 세션 중 9개가 빠진 뒤 `--continue`로 두 번 재시작했으나 그대로였다)
- **`sync`는 사본 폴더를 다시 깔아 두는 명령이다.** 다음 세션과 다른 작업자가 쓸 사본을 준비하는 용도이고, 지금 세션의 목록을 복구하지는 못한다. 새 에이전트 정의도 다음 세션부터 잡힌다.
- **`.claude/agents/`는 모든 Claude 세션이 같이 쓴다.** 어느 Claude 세션이든 끝나면 SessionEnd 훅이 이 폴더를 통째로 지운다. Orca Claude 작업자의 종료도 포함된다(2026-11-25, Fable 작업자를 중지한 직후 폴더가 사라진 것을 확인했다). 그래서 Claude 작업자를 닫은 뒤에는 `node .claude/hooks/session-agents.js sync`로 사본을 다시 깐다. 근본 수정은 `.claude/UNFINISHED.md` 항목에 있다.
- 2026-11-25 세션 중 `quick-fix`가 목록에서 빠진 원인은 확정하지 못했다. `sync`는 파일을 복사만 하므로 직접 원인은 아니다. 다른 세션 종료 때 실행된 cleanup이 유력한 후보다.
- **위임할 수 없는 상태면 조용히 직접 처리하지 말고 그 사실을 먼저 알린다**(2026-08-24). 기본 경로는 Orca 작업자이고, Agent 도구는 Orca 작업자로 띄울 수 없을 때만 쓴다(`AGENT.MD` 「Claude 역할 에이전트 실행 방식」). 상세는 `ParallelWorkContract.MD` §11.
