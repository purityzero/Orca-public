# 목표 중심으로 실행하기

마지막 적용: 2026-11-05

`CLAUDE.md`에서 상황별 절차·근거를 원문 그대로 옮겼다. 해당 주제를 작업하기 전에 읽는다.

## 목표 중심으로 실행하기

**성공 기준을 먼저 정의한다. 검증에 통과할 때까지 반복한다.**

작업을 검증 가능한 목표로 변환한다:
- "유효성 검사 추가해줘" → "잘못된 입력에 대한 테스트를 먼저 작성하고, 그것을 통과시킨다"
- "버그 고쳐줘" → "버그를 재현하는 테스트를 작성하고, 그것을 통과시킨다"
- "X 리팩토링해줘" → "리팩토링 전과 후 모두 테스트가 통과하는지 확인한다"

여러 단계가 필요한 작업이라면 간단한 계획부터 제시한다.

1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]

성공 기준이 탄탄하면 혼자서도 루프를 돌며 작업할 수 있다. 기준이 허술하면("일단 되게 해줘") 매번 되물어야 한다.

## 같은 시도를 반복하지 않는다 — 2~3회 실패하면 멈추고 원인을 찾는다

- 진단·탐색 중 같은 계열의 시도(경로만 바꿔가며 찾기, 명령 변형해 재실행 등)가 **2~3회 연속 실패하면 거기서 멈춘다.** 더 많은 후보를 찍어보는 대신, 이미 나온 결과가 무엇을 말하는지 먼저 해석한다.
- 첫 한두 번의 실패가 이미 원인을 가리키는 경우가 많다 — 예: `node`가 bash와 PowerShell 양쪽에서 안 잡히면 그 시점에 "설치 안 됨 / PATH 없음"이 사실상 결론이다. 표준 설치 경로를 5곳 더 뒤지는 건 왕복만 늘린다.
- 원인을 특정한 뒤에 필요한 확인만 1회 더 한다. "혹시 몰라서" 추가 탐색은 하지 않는다.
- (근거: 2026-09-04, 훅 미실행 진단 중 node 부재를 두 번에 확인하고도 설치 경로 탐색을 5~6회 더 돌렸다. 사용자 지적)

## Codex와의 작업 경계
Codex 역할·프로필·완료 조건은 `CODEX.md`를 따른다.
- `CODEX.md`에 정의된 저장소 전체 분석·자동화·테스트·리팩터링·문서 정합성 작업은 Codex의 우선 소유 영역이다. 해당 작업을 Claude Code에만 고정하지 않는다.
- Codex와 협업하거나 비교 실행할 때는 `AGENT.MD`의 실행자 선택과 `ParallelWorkContract.MD`의 파일 소유권·평가 계약을 따른다.
- Codex가 이미 소유한 파일을 동시에 수정하지 않는다. Unity MCP·Play Mode는 Codex가 맡고, 배타 자원 검증 결과는 파일 변경과 분리해 전달한다.
- Codex가 끝까지 수행 가능한 작업은 구현·검증까지 소유하며, 검증되지 않은 우열을 고정하지 않고 실측 결과로 배정을 갱신한다.
- 최종 stage·commit·merge·push와 병합 완료 브랜치 삭제는 Codex 메인 세션이 담당한다. Claude Code와 그 서브에이전트는 변경 파일, 검증 결과, 남은 위험을 보고하고 Git 마무리를 요청한다.

## 작업 경계와 세션 리셋 (Claude·Codex 공통)
- **독립된 새 목표는 새 대화로 시작한다** — 같은 탭에서 Claude `/clear`, Codex `/new`. 같은 목표의 수정·검증·커밋·요청된 push는 이어간다.
- **인계가 열려 있으면 리셋하지 않는다.** 반환 도착·산출물 회수·사용자 요약까지 끝나야 닫힌다.
- 일회성 승인(커밋·push 등)은 새 대화로 넘어가지 않는다. 리셋이 상시 권한을 취소하지도 않는다.
- 작업 시작 시 Orca 탭 이름을 작업명으로, 리셋 직전 `.local/session-log.md`(로컬 전용)에 세션 ID·결과·다시 여는 명령을 남긴다.
- 체크리스트·로그 형식·실측·주의(Git Bash가 `/clear`를 경로로 바꿈, 에이전트 사본 공용 폴더)는 `runbook/session-reset.md`. (근거: 2026-11-05)

## 미완료 작업 (세션 시작·진행 중)

- 세션에서 처음 호출되면 `.claude/UNFINISHED.md`를 확인해 남은 작업을 첫 응답에서 알린다. 끝내면 그 항목을 제거한다.
- **워크스페이스 루트 세션**은 SessionStart 훅이 번호 매긴 Unity Hub 목록을 세션이 열리는 즉시 화면에 출력한다.
  같은 목록을 응답에서 다시 나열하지 않는다. 사용자가 고르기 전에 임의로 고르지 않는다. 고른 직후 두 가지를 한다 —
  ① `OpenUnityProject.ps1 -ProjectPath "<절대경로>"`로 에디터 실행(MCP는 에디터 로드 후 자동 연결)
  ② `.claude/session-project/{세션ID}.json`에 확정 기록(안 적으면 UserPromptSubmit 가드가 매 턴 미확정 알림을 띄운다).
- **검증 못 한 작업이 생기는 그 시점에** 날짜·남은 작업·검증 항목·관련 파일·브랜치를 UNFINISHED에 적는다.
  특히 **커밋을 하나 만들 때마다** 그게 검증된 것인지 판단하고, 아니면 그 자리에서 반영한다.
  검증 수단이 없는 환경(에디터 미연결 등)이면 그 사실과 이유도 적는다. 이미 항목이 있으면 새로 만들지 말고 갱신한다.
  (근거: 2026-08-26. "세션이 끝날 것 같으면"이라는 조건이 한 번도 발동하지 않아, 미검증 커밋 9개가 쌓이는 동안 기록이 비었다)

## 코딩보다 생각이 먼저다

**가정하지 않는다. 혼란을 숨기지 않는다. 트레이드오프를 드러낸다.**

구현하기 전에:
- 전제하고 있는 가정을 명시적으로 말한다. 확신이 없으면 묻는다.
- 여러 해석이 가능하면 모두 제시한다. 말없이 하나를 고르지 않는다.
- 더 단순한 접근이 있다면 말한다. 타당하다면 반대 의견도 낸다.
- 불명확한 부분이 있으면 멈춘다. 무엇이 헷갈리는지 명확히 하고 질문한다.

## 모호한 요구사항 확인 방식

- 표시값/계산 공식처럼 정답이 여러 갈래로 갈리는 요구사항은, "A로 할까요 B로 할까요" 같은 추상적 질문을 반복하지 말고 **구체적인 예시 숫자/케이스**로 먼저 제시해 확인한다 — 추상적 질문 반복은 왕복 횟수만 늘리고, 원치 않는 방향으로 구현부터 해버리면 반려당하는 비용이 크다.

### 공통 안내·근거의 원문 보존

LLM이 코딩할 때 흔히 저지르는 실수를 줄이기 위한 행동 지침이다. 필요하면 프로젝트별 지침과 합쳐서 사용한다.
**트레이드오프:** 이 지침은 속도보다 신중함을 우선한다. 사소한 작업에서는 상황에 맞게 판단한다.
클래스·프리팹 수정 및 기록 md 생성·갱신 전에 읽는다. 대응 md를 먼저 확인·읽고 수정 후 기록과 기획/설계 문서를 실제 상태로 갱신한다. 런북: `runbook/document-records.md`(md 읽기/생성/갱신, class·prefab md 생성 규칙 포함).
실수를 알아차리면 런북·메모리를 먼저 검색한다. 피드백·정정·재발 처리 또는 공용 규칙 저장 전에 읽는다. 런북: `runbook/feedback.md`(피드백 반영 프로세스, 승격 사다리 포함).
성공 기준을 먼저 정의하고 검증에 통과할 때까지 반복한다. 검증 가능한 목표·단계별 계획 수립 전에 읽는다. 런북: `runbook/task-execution.md`.
검증 설계·실행·결과 해석 전에 읽는다. 사용자의 실제 프로덕션 진입 경로와 결과물을 검증한다. 런북: `runbook/verification-paths.md`.
같은 계열 시도가 2~3회 연속 실패하면 멈추고 결과를 해석한다. 반복 실패 진단 전에 읽는다. 런북: `runbook/task-execution.md`.
