# Runbook — 검증 스크립트

마지막 적용: 2026-09-10 (오탐 2건)

## ★ 검사 도구가 틀리면 정상을 결함으로 보고한다

폰트 감사 스크립트가 **정상인 6개 파일을 전부 결함으로 보고**한 적이 있다.

```python
# ❌ 음수 fileID를 못 잡는다
re.findall(r'm_sharedMaterial: \{fileID: (\d+), guid: ([0-9a-f]{32})', s)
```

`PressStart2P`의 머티리얼 fileID가 **`-6700491040415472100`**(음수)이라
`(\d+)`가 매치되지 않았고, 스크립트는 "머티리얼 0건"으로 읽어 짝 불일치 6건을 냈다.
실제로는 65:65로 정확히 맞아 있었다.

```python
# ✅
re.findall(r'm_sharedMaterial: \{fileID: (-?\d+), guid: ([0-9a-f]{32})', s)
```

**하마터면 Codex가 옳게 한 일을 "결함"으로 되돌릴 뻔했다.**

### 같은 날 두 번째 오탐 — stretch 앵커

좌표 검사 스크립트가 **배경 오브젝트를 겹침으로 보고**했다. `m_SizeDelta`를 크기로 읽었는데,
**앵커가 stretch(min != max)면 `sizeDelta`는 크기가 아니라 여백(offset)**이다.
48x16으로 읽힌 것이 실제로는 화면 전체를 덮는 배경이었고, `raycastTarget`도 0이라
클릭을 막지도 않았다.

### 그래서

1. **검사기가 입력 형식을 좁게 가정하지 않았는지 먼저 본다.** 이게 핵심이다.
   - 숫자: **음수 · 0 · 과학적 표기 · 빈 값**
   - Unity RectTransform: **stretch 앵커면 sizeDelta의 의미가 바뀐다**
   - 같은 필드가 문맥에 따라 다른 뜻을 갖는 경우가 있는지
2. **"전부 실패"는 검사기 버그의 강한 신호다.** 진짜 결함은 보통 일부에만 난다.
   다만 **일부만 실패해도 검사기가 틀릴 수 있다**(위 stretch 사례가 그랬다) —
   이 신호만 믿으면 안 된다.
3. **정상 케이스로 검사기를 먼저 통과시켜 본다** — 알려진 정상 입력에 통과가 나오는지.
4. **런타임 값과 대조할 수 있으면 한다.** 위 두 건 모두 파일을 파싱해 추론한 결과였고,
   에디터에서 실제 값을 읽은 쪽이 맞았다. **정적 파싱은 추론이고 런타임은 사실이다.**

## 판정 방법을 결함 주입으로 검증한다

"결손 0"이 나왔을 때, **일부러 결함을 넣어 판정이 실제로 깨지는지** 1회 확인한다.
안 깨지면 그 판정은 무효다.

실제로 `HasCharacter()` 기반 판정이 "결손 0"을 냈는데, 없는 글자를 주입해도 여전히 0이 나와
판정 자체가 무의미했음이 드러났다 → [unity-font.md](unity-font.md)

## 부정 경로를 반드시 포함한다

성공 경로만 재면 **제한이 안 걸린 구현도 통과한다.**

- "2회까지만 살 수 있다" → **3회째가 막히는지**를 계수로 단언
- "골드가 부족하면 못 산다" → 눌러도 **값이 안 변하는지**
- "0이 되면 끝난다" → 0인데 **다른 수단이 있으면 안 끝나는지**까지

## 화면 값을 읽되, 그 값에 무엇이 더해지는지 안다

QA 기대값을 "코인 5"로 적었는데 화면엔 8이 나와 **기능 정상인데 실패로 보고**된 적이 있다.
`RunData.Init()`이 메타 업그레이드 보너스를 더하고 있었다.

→ 기대값을 쓸 때 **원본 설정값**과 **화면에 나오는 최종값**을 구분해 각각 확인하게 한다.
→ 브리프에 "화면 숫자만 보고 판정하지 마라"를 적는다.

## 측정이 조건을 바꾸지 않게

프레임 기반 동작을 잴 때 **녹화를 켜면 프레임레이트가 떨어져 측정 대상이 달라진다.**

실측: 릴 정지 소요가 52fps에서 1.00초, 23fps(녹화 중)에서 1.69초.
녹화 영상으로는 배너 등장 프레임을 특정하지 못했다(페이드인 0.12초 vs 캡처 21fps).

→ **`EditorApplication.update`마다 값을 동시 샘플링해 CSV로 남기는 방식**이 정확했다.
→ 타이밍 검증에는 영상보다 계측을 쓴다.

## 고정 시간 대기로 프레임 기반 동작을 맞추지 않는다

감속이 **프레임당 이동량** 기반이면 소요 시간이 프레임레이트를 탄다.
`WaitForSeconds(고정값)`으로는 원리상 맞출 수 없다.

```csharp
// ❌ 프레임레이트에 따라 이르거나 늦다
yield return new WaitForSeconds(0.9f);

// ✅ 실제 완료를 묻는다
yield return new WaitUntil(() => target.isAllReelIdle);
```
